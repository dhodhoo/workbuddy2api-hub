API Key exit binding

Bind a dedicated exit to each key. Requests made with that key always take the matching region, so both exits run concurrently.

Proxy slots

Every account is pinned to one exit proxy slot. When the slot address changes the bound accounts follow automatically; disabling or deleting the slot falls back to a direct connection.

Limits

All four guardrails follow the Global default and apply to Global and China; set a value for one realm when you need to, or leave it empty to inherit the Global default. 0 turns that guardrail off.
Guardrail Global default Global China
Reserved credits
An account stops taking orders once its balance drops below this, so the balance never drains far enough to trigger the upstream SMS alert.
Daily token limit
Once an account has used this many tokens today it stops taking orders and requests move to another account; it recovers after local midnight. Independent of Reserved credits - either one pauses order taking.
Daily credit limit
Once an account has spent this many credits today only free models are served (those marked x0.00 in the catalog), and models that cost credits move to another account; it recovers after local midnight.
Daily token limit per model
Once an account has used this many tokens on one model today that model moves to another account (the account's other models are unaffected); it recovers after local midnight.

OpenRouter estimate

Converts the tokens of every request into CNY using the price of the same-named model on OpenRouter, feeding the "OpenRouter estimate" column and the "API-equivalent cost" card. On by default; with it off no prices are fetched and no amount is converted, and the related columns, cards and fetch controls are hidden (only this switch stays). Turning it back on back-fills the requests made while it was off: those requests are converted with the first price fetched afterwards and marked *, so turning it off and on again loses nothing.
Estimation is off: no prices are fetched and no amount is converted, and the price column and the API-equivalent cost card are hidden; turning it back on back-fills the requests made while it was off.

Price refresh

The gateway fetches prices from OpenRouter every so often: each distinct price set of a model is stored as onePricing policy(identical content reuses the same row instead of writing a duplicate), and states which one is in effect. Every request is priced by whichever policy was in effect when it happened, so later price changes never rewrite earlier numbers; a request only records which policy it referenced, not a copy of the whole price table. A model with no price at fetch time is back-filled from the first price fetched later and marked with *. Policies nobody references and that are no longer valid get cleaned up (every model keeps at least one, and the batch just fetched is left alone). The fetch interval is counted inminutes; the default is 5 minutes. 0 turns automatic fetching off (you can still fetch once with Fetch prices now).
Price input = built-in catalog ∪ models newly added to the live catalog of the gateway; names upstream has just listed enter the next price fetch with no code change, and a new model called between two fetches isprice on demand. Names carrying a channel suffix (such as -lkeap) are, by default,Variant suffix inheritancepriced from the base model (a unique match is required, otherwise it still shows as unpriced); turning the switch off restores pricing from the override table and same-name matches only.

429 auto-switch outbound identity

When an account is rate-limited upstream (429) on a model, retry automatically while switching identity among WB / VSC / CLI, up to 4 times per round. The three identities use different quota channels, so 429s become less frequent. Off by default.
Note: the switched identity is saved and kept after a restart; it does not go back to WB on its own.

Global daily activity check-in

When a Global account checks in, besides the light desktop-identity chat it also runs one web-channel session (a session with a prompt is created under console/as). In practice only web-side chats count toward the official daily activity; desktop-identity chats do not. On by default.
Note: the web channel really runs a task and spends a few credits from that account, in exchange for the daily 30/50 credit activity reward.

Local web tools (web_search / web_fetch)

Some clients (such as the Codex App) declare server-side tools like web_search / web_fetch, but the upstream has no executor for them: the declaration goes up, the model sees the tool with nothing to run it, and the client ends up with nothing but unsupported call. With this on, the gateway runs them instead: it swaps the declaration for its own same-named function, runs it locally (search through DuckDuckGo, page fetch for that URL) and feeds the result back to the model. Off by default; when off the declaration passes through untouched and search tools the client declares itself still get called.
Note: with this on, the gateway goes out to fetch the URLs the model asks for (only literal private addresses are blocked), and every proxied round makes one extra upstream call and spends more of that account quota; on Chinese networks DuckDuckGo may be unreachable, and the model then gets error text.
